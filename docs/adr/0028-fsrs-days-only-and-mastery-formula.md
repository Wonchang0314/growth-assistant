# ADR-0028: FSRS 단기 학습 단계를 끄고 최대 간격을 180일로 줄이며, 대화에서 다룬 개념을 복습 일정에 넣고, 숙련도·약점 공식과 개념 병합 규칙을 정한다

- 상태: 채택
- 날짜: 2026-10-18
- ADR-0016의 "기본 파라미터로 시작"에서 단기 학습 단계와 최대 간격을 바꾼다. 설계 문서 8장의 약점 공식을 구체화하면서 확신도 보정을 곱셈에서 덧셈으로 바꾼다. 애매하게 맞힌 답은 0.5점으로 센다. 나머지(ts-fsrs 사용, 개념 단위 복습, 하루 10문제, 등급 매핑, 힌트 없는 응답만 반영)는 그대로다.

## 맥락

3단계에서 `tutor/mastery`를 만들며 세 가지를 정해야 했다.

1. **단기 학습 단계.** `ts-fsrs` 5.4.2(FSRS-6)의 기본값은 `enable_short_term: true`, 학습 단계 1분·10분, 재학습 단계 10분이다([ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs), 2026-10-18 `npm view`와 패키지 상수로 확인). 카드 앱에서 같은 카드를 몇 분 뒤 다시 보여 주는 장치다. 이 프로젝트는 개념 단위로, 하루 최대 10문제를, Claude 대화에서 사용자가 "복습하자"고 할 때 낸다. 같은 개념이 1분·10분 뒤 다시 예정되면 같은 대화에서 같은 개념만 되풀이하거나, 예정 시각이 이미 지난 채로 다음 날까지 남는다.
2. **대화에서 다룬 개념의 일정.** 설계는 대화 결과로 점수를 바꾸지 않고 CONFUSED는 출제 우선순위만 올린다고 한다(ADR-0009). 그런데 복습 일정이 없는 개념은 출제 우선순위 ①(복습할 때가 된 개념)에 들지 못하고, ③ 새 개념으로 트랙 가중치에 따라 뽑혀야 나온다. 대화에서 배운 개념을 다음 복습에서 확인하지 못할 수 있다.
3. **숙련도·약점 공식.** 설계 8장은 "최근 가중 정답률(지수이동평균)", "(1 − 숙련도) × 확신도 보정 + 반복 오개념 가산점"까지만 적었다. 확신도 보정을 곱셈으로 하면 숙련도가 높을 때 확신한 오답의 신호가 거의 사라지고, 그 보정을 계산하려면 지난 확신도 기록을 따로 들고 있어야 한다.

## 결정

### 1. 단기 학습 단계를 끄고 최대 간격을 180일로 줄인다

- `generatorParameters({ enable_short_term: false, maximum_interval: 180 })`. 나머지는 기본값이다: 목표 기억률 0.9, 간격 흔들기(fuzz) 끔, FSRS-6 기본 가중치 21개.
- 기본 최대 간격 36500일은 사실상 상한이 없어, 잘 아는 개념이 몇 년 동안 다시 나오지 않는다. 면접 대비가 목표라 모든 개념을 반년에 한 번은 확인한다(사용자 결정 2026-10-18). `ts-fsrs`는 180일로 자른 뒤 Hard < Good < Easy 간격을 하루씩 벌리므로 실제 최대는 181~182일이다.
- 간격은 언제나 하루 이상이다. 새 개념의 첫 간격은 Again 1일, Hard 2일, Good 3일, Easy 8일이다(5.4.2 기준, `fsrs.spec.ts`에 기대 값으로 남김). 상태는 NEW와 REVIEW만 생기고, 테이블의 LEARNING·RELEARNING은 설계대로 남겨 둔다.
- `ts-fsrs`는 5.4.2로 고정한다. 6.0은 베타(2026-10-18 `6.0.0-beta.14`)이고 `elapsed_days` 같은 필드를 없앤다. 올릴 때 기대 값 테스트로 차이를 본다.

### 2. 학습 기록에서 다룬 개념은 복습 일정에 넣는다

- `record_study_note`가 연결한 개념(DISCUSSED·CONFUSED 모두)에 일정이 없으면 NEW 일정을 만들고 예정 시각을 기록 시각으로 둔다. 다음 `get_review_set`에서 ① 복습할 때가 된 개념에 든다.
- 이미 일정이 있으면 건드리지 않는다. 점수도 바꾸지 않는다(ADR-0009 그대로). CONFUSED는 출제할 때 학습 기록(`study_note_concept`)에서 읽어 ② 우선순위에 쓴다.

### 3. 숙련도·약점 공식

힌트 없이 낸 응답만 반영한다. 힌트를 쓴 응답은 FSRS 일정만 바꾼다.

```
credit  = 정답이면 확실 1, 애매 0.5, 찍음 0. 오답은 0
penalty = 오답일 때만: 확신했으면 +0.5, 같은 오개념이 전에도 나왔으면 +0.5
mastery_score  = EMA(credit)
weakness_score = min(1, EMA(1 − credit + penalty))
EMA(x) = 첫 응답이면 x, 그 뒤로 0.4·x + 0.6·이전 값
```

- 지수이동평균이 선형이라 `weakness_score`는 "(1 − 숙련도) + 확신한 오답 가산점의 평균 + 반복 오개념 가산점의 평균"과 같다(1로 자르기 전). 지난 응답 기록 없이 행 하나로 갱신한다.
- 최근 가중치 0.4는 최근 4~5번의 응답이 점수의 대부분(1 − 0.6⁵ ≈ 92%)을 정하게 한 값이다.
- 채점된 응답이 2회 미만이면 미측정, 그 이상에서 `weakness_score ≥ 0.5`면 약점이다(설계 8장 그대로).
- 같은 오개념이 반복됐는지는 풀이 기록을 가진 `quiz`가 판단해 넘긴다. `mastery`는 퀴즈 테이블을 모른다.

### 4. 개념 병합 때 학습 기록·복습 일정을 옮긴다

- `core`는 `tutor` 테이블을 모르므로 `core/knowledge`에 병합 참여 포트(`ConceptMergeParticipant`)와 등록 목록(`ConceptMergeParticipants`)을 둔다. `tutor` 모듈이 시작할 때(`onModuleInit`) 자기 저장소를 등록하고, `review_concept`의 병합이 같은 트랜잭션 안에서 참여자를 부른 뒤 개념을 지운다.
- 학습 기록 연결은 대상 개념으로 옮긴다. 한 기록에 두 개념이 다 있으면 한 번이라도 CONFUSED면 CONFUSED를 남긴다.
- 복습 일정·숙련도는 대상에 행이 없으면 원래 행을 옮기고, 둘 다 있으면 채점된 응답이 더 많은 쪽 행 하나만 남긴다(같으면 대상). 두 FSRS 상태를 섞지 않는다.
- 퀴즈 문제·풀이는 `quiz` 모듈을 만들 때 같은 포트로 개념 ID를 옮긴다.
- 참여자를 등록하지 않은 진입점(수집 CLI)에서 병합하면 지금처럼 외래 키가 막는다.

## 결과

- 좋은 점
  - 복습 일정이 하루 단위라 "오늘 복습할 개념"이 분명하고, 한 대화 안에서 같은 개념을 되풀이하지 않는다.
  - 대화에서 배운 개념이 다음 복습에 바로 나와, 대화 → 퀴즈 확인 흐름이 이어진다.
  - 공식이 행 하나로 계산되고 순수 함수라 테스트로 고정된다.
- 나쁜 점·감수할 것
  - 틀린 개념을 같은 날 다시 확인하지 않는다(가장 빨라도 다음 날). 같은 대화에서 다시 묻는 것은 Claude의 튜터링 대화가 맡는다.
  - 대화에서 여러 개념을 다루면 다음 복습에 그만큼 쌓인다. 하루 10문제 상한과 우선순위로 자른다.
  - 신고된 문제의 풀이를 나중에 빼려면 점수를 풀이 기록으로 다시 계산해야 한다. 공식이 응답 순서대로 접는(fold) 순수 함수라 퀴즈 기록이 생기면 다시 계산할 수 있다.
  - 가중치·가산점·문턱 값은 감으로 정했다. 실제 풀이가 쌓이면 다시 본다.

## 검토한 대안

- **기본값(단기 학습 단계 켬) 그대로:** ADR-0016의 "기본 파라미터"에 가장 가깝지만, 위의 이유로 개념 단위·대화 단위 복습과 맞지 않는다.
- **CONFUSED면 예정일을 지금으로 당기기:** 헷갈린 개념을 바로 확인하지만, 설계의 우선순위(CONFUSED는 ②)를 ①로 바꾸고 FSRS 일정을 대화가 흔든다.
- **설계 그대로 곱셈 보정:** 보정 값을 계산하려면 확신도 기록이 따로 필요하고, 숙련도가 높을 때 확신한 오답이 거의 드러나지 않는다.
- **애매한 정답도 1점:** 설계 8장 등급 표가 애매한 정답을 Good(정답)으로 보고, 확신도 차이는 FSRS 등급(Good·Easy)이 이미 반영한다. 하지만 설계 8장 원칙은 "확신을 갖고 답한 응답"만 숙련도로 인정하므로 반만 센다(사용자 결정 2026-10-18).
- **병합 때 두 숙련도 행을 평균:** 두 FSRS 상태를 섞으면 어느 쪽 기억도 아닌 값이 된다.
- **`core` 병합 코드가 `tutor` 테이블을 직접 옮기기:** 빠르지만 `core`가 `tutor`를 모른다는 의존 규칙(ADR-0015)을 깬다.

## 재검토 조건

복습 기록이 수백 건 쌓이면 FSRS 파라미터 최적화(ADR-0016)와 함께 가중치·가산점·문턱 값을 다시 본다.

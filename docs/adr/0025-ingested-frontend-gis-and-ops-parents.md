# ADR-0025: 수집한 경험의 프런트엔드·GIS 개념을 받고, 운영 경험을 묶을 상위 개념 3개를 시드에 둔다

- 상태: 채택
- 날짜: 2026-10-18
- ADR-0022의 2절 중 두 부분을 대체한다. "프론트 심화(React, TanStack Query 등) 트랙은 없앤다"는 수집 개념에는 적용하지 않고, "nginx, CI/CD, 인증서 발급, SSH 키 같은 운영 개념은 뺐다"는 상위 개념 3개만 되돌린다. 트랙 6개와 가중치, 시드가 커리큘럼이라는 원칙(1절)은 그대로다.

## 맥락

경험 카드 백필(문서 164개, 카드 545장)에서 새 개념 81개가 제안됐고 Desktop 대화로 모두 검토했다(2026-10-18). 두 가지가 드러났다.

1. **업무 경험의 상당 부분이 프런트엔드·GIS다.** ADR-0022는 프론트 심화를 학습 목표에서 뺐지만, 경험은 React 리렌더링·TanStack Query·WebGL 렌더링 모델·공간 인덱스 같은 개념에 걸려 있다. 처음에는 범위 밖이라 전부 거절할지 검토했지만, 사용자가 "전부 거절은 너무 박하다, 너무 좁거나 지엽적인 것만 뺀다"고 정했다. 개념이 없으면 그 카드는 학습 맥락에 나오지 않고 글자 검색으로만 찾는다.
2. **운영 경험이 상위 개념 없이 흩어져 있다.** CI 잡 직렬화, CI Runner 태그 라우팅, SSH 푸시 배포, 헬스체크와 롤백, systemd 서비스 유닛, nginx 지시어 상속 같은 개념이 승인됐지만 묶을 상위 개념이 시드에 없다. 상위가 없으면 학습 맥락에서 관련 개념으로 이어지지 않고, 숙련도·약점도 개념마다 따로 흩어진다.

## 결정

### 1. 수집한 프런트엔드·GIS 개념을 받는다

- 프런트엔드 개념은 `js` 트랙, GIS 개념은 `database` 트랙에 둔다. 새 트랙은 만들지 않는다.
- 받는 기준은 "여러 경험에 다시 쓰일 일반 개념"이다. 라이브러리 API 하나(deck.gl `updateTriggers`), 이 프로젝트에서만 쓰는 규칙, 좁은 CSS 기법(텍스트 말줄임, CSS 폭 키워드)은 거절한다.
- 시드 커리큘럼은 그대로다. 프런트엔드·GIS 개념은 수집과 검토로만 들어온다.
- 추출 프롬프트도 이 트랙을 고르게 한다. 상위 개념이 맞지 않으면 지금처럼 승인 대기로 둔다.

### 2. 운영 상위 개념 3개를 `infra` 시드에 둔다

| 개념 | 상위 | 선수 | 묶을 수집 개념 |
|---|---|---|---|
| CI/CD 파이프라인 | 없음 | Docker | CI 잡 직렬화, CI Runner 태그 라우팅, CI 잡 실행 조건 rules, CI 파이프라인 구조 |
| 배포 전략 | CI/CD 파이프라인 | | SSH 푸시 배포, 헬스체크와 롤백 |
| 리눅스 서버 운영 | 없음 | 프로세스와 실행 | systemd 서비스 유닛, 무인 자동 업데이트, nginx 지시어 상속, SSH 키 인증 |

- 커리큘럼(강의) 순서와 상관없이 수집 개념을 묶는 자리다. 강의 범위 밖이라는 ADR-0022의 판단은 하위 세부 개념에는 그대로 두고, 시드에는 이 셋만 넣는다.
- GitLab CI·GitHub Actions 같은 도구 이름은 별칭에 넣지 않는다. 도구를 물을 때 이 개념이 걸리면 학습 맥락이 넓어진다.
- `롤백`·`rollback`은 별칭에 넣지 않는다. 관계형 DB의 `ROLLBACK`(트랜잭션과 ACID)과 겹치고, 배포 롤백은 수집 개념 "헬스체크와 롤백"이 맡는다.
- 수집 개념의 상위는 배포한 뒤 `review_concept` APPROVE의 `parent`로 지정한다. 시드 YAML에는 수집 개념을 적지 않는다(시드 적재는 시드 개념만 다룬다).

## 결과

- 좋은 점
  - 프런트엔드·GIS 경험 카드도 학습 맥락에 나와 대화에서 경험을 인용할 수 있다.
  - 운영 경험이 상위 개념 아래로 모여 "CI/CD 공부하자"에서 관련 경험이 함께 나온다.
- 나쁜 점·감수할 것
  - `js`·`database` 트랙에 학습 목표 밖의 개념이 섞인다. 트랙별 숙련도에 프런트엔드·GIS가 함께 잡힌다. 따로 보고 싶어지면 트랙을 나누는 새 ADR을 쓴다.
  - 받을지 말지는 "여러 경험에 다시 쓰일 일반 개념"이라는 판단 기준에 기댄다. 검토 때 사람이 정한다.

## 검토한 대안

- **프런트엔드·GIS 개념을 전부 거절:** 학습 목표와 맞지만 업무 경험의 큰 부분이 학습 맥락에서 사라진다. 사용자가 너무 박하다고 했다.
- **프런트엔드·GIS 트랙 새로 만들기:** 숙련도가 깔끔하게 나뉘지만 가중치가 생겨 새 개념 고르기(ADR-0021)에 끼어든다. 커리큘럼이 없는 트랙이라 지금은 이르다.
- **운영 상위 개념을 수집 개념으로 만들기(검토 도구로):** 시드를 건드리지 않지만, 카드가 없는 개념은 수집으로 생기지 않고, 상위 개념은 사람이 정한 뼈대라 YAML에 두는 편이 맞다.

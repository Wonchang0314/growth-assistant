# ADR-0019: 핵심 학습 기능을 먼저 만들고, 퀴즈는 객관식·빈칸부터, 먼저 말 걸기·알림·인증·보안은 뒤로 미룬다

- 상태: 채택
- 날짜: 2026-10-15

## 맥락

ADR-0018은 아침·저녁 학습을 맥미니에서 실행되는 Claude 예약 작업(Cowork, 안 되면 Claude Code 데스크톱 예약 작업)으로 하기로 했고, 예약 작업이 로컬 MCP를 쓸 수 있는지는 1단계에서 검증하기로 했다. 2026-10-14에 사용자가 확인한 결과는 다음과 같다.

- Cowork 예약 작업은 로컬 MCP 서버를 쓸 수 없다.
- Claude Code 클라우드 루틴은 Anthropic 클라우드에서 돌아 로컬 MCP에 닿지 않는다.

그래서 "아침·저녁 학습은 맥미니의 Claude 예약 작업으로" 계획이 지금은 성립하지 않는다. 남은 후보(Claude Code 데스크톱 예약 작업, 원격 전환 뒤의 예약 작업)를 지금 검증하려면 학습 기능보다 실행 경로에 먼저 시간을 쓰게 된다.

사용자의 방향은 학습 촉진이라는 본질에 집중하는 것이다. 부가 기능과 인증·보안은 나중에 고민한다.

퀴즈 유형도 같은 기준으로 다시 봤다. 설계에는 객관식·빈칸·서술형이 있다. 서술형(기술적 판단·트레이드오프 서술, 면접형 경험 서술)은 정답이 하나가 아니어서 채점 기준표와 `claude -p` 채점이 필요하다. 그만큼 채점이 느리고, 채점 품질 자체를 따로 검증해야 하며, 사용량 한도에 걸리면 채점이 보류된다. 객관식과 빈칸은 코드가 즉시, 결정적으로 채점한다.

## 결정

핵심 학습 기능을 먼저 만들고 검증한다. 먼저 말 걸기, 알림, 인증·보안은 뒤로 미룬다.

| 영역 | 선택 |
|---|---|
| 우선순위 | 튜터링 대화, 기억 연결(Notion·velog), 퀴즈·복습, 숙련도·약점을 먼저 만든다 |
| 퀴즈 유형 | 객관식(`MULTIPLE_CHOICE`)과 빈칸(`FILL_BLANK`)만 먼저 만든다. 채점은 코드가 하고 `claude -p`를 부르지 않는다 |
| 서술형 | 미룬다. 기술적 판단(트레이드오프) 서술 문제와 면접형 경험 서술 연습을 포함한다. 객관식·빈칸 품질을 확인한 뒤 채점 기준표와 함께 다시 설계한다 |
| 아침·저녁 학습 | 미룬다(07:30 아침 복습, 18:30 오늘의 주제, 일요일 주간 리포트). 그동안은 Claude Desktop 대화에서 "복습하자"처럼 직접 시작한다 |
| 예약 작업 실행 방식 | 4단계에서 핵심 기능을 검증한 뒤 정한다. 후보: Claude Code 데스크톱 예약 작업, 원격 전환 뒤의 예약 작업 |
| 알림·인증·보안 | 원격 전환(5단계)에서 새 ADR로 정한다(ADR-0018 그대로) |

ADR-0018의 "아침·저녁 학습" 행을 대체한다. 나머지(로컬 stdio MCP, 서버 채점, 전송 분리, 원격 전환 순서)는 그대로다.

## 결과

- 좋은 점
  - 1단계에서 예약 작업 검증을 빼고 MCP 진입점과 도구에 바로 들어간다.
  - 객관식·빈칸은 채점이 즉시 끝나고 결과가 결정적이다. 사용량 한도와 상관없이 복습을 이어 가고, 숙련도 계산이 LLM 채점 오차에 흔들리지 않는다.
  - 퀴즈 품질 검증을 출제·검증 품질에 집중할 수 있다.
- 나쁜 점·감수할 것
  - 학습을 사용자가 직접 시작해야 한다. 복습할 때가 됐는지는 `get_review_set`이 알려 주지만, 열어 보지 않으면 모른다.
  - 객관식은 알아보기(재인)만으로 풀 수 있어 떠올리기(회상)보다 기억 효과가 약하다. 빈칸을 섞고, 오답 보기를 내 실제 오개념으로 만들어 보완한다.
  - 1순위 트랙(취업·면접)의 핵심인 "내 경험을 말로 설명하기"와 트레이드오프 판단 서술은 서술형을 만들 때까지 퀴즈로 연습하지 못한다. 그동안은 튜터링 대화에서 연습한다.
  - 빈칸은 허용 답(`accepted_answers`)에 없는 맞는 답을 틀렸다고 채점할 수 있다. 빈칸 자리를 답이 거의 하나로 정해지는 용어로 고르고, 잘못 채점되면 `report_question`으로 신고한다.

## 검토한 대안

- ADR-0018대로 1단계에서 예약 작업 경로를 먼저 검증: Cowork가 안 되는 것을 확인했고, 남은 후보를 검증하는 동안 학습 기능이 늦어진다.
- 서술형을 처음부터 함께 만들기: 판단력 검증에는 가장 좋지만, 채점 기준표·`claude -p` 채점·채점 품질 검증·보류 채점까지 같이 만들어야 한다. 퀴즈 흐름 전체를 확인하기 전에 가장 불확실한 부분을 먼저 만들게 된다.
- 원격 전환을 앞당겨 클라우드 루틴으로 아침·저녁 실행: 공개 경로와 인증을 먼저 만들어야 해서 ADR-0018의 "품질 먼저" 순서와 맞지 않는다.

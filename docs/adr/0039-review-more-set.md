# ADR-0039: 하루 10문제를 다 푼 뒤 사용자가 더 풀겠다고 하면 오늘 푼 개념을 뺀 10문제를 더 낸다

- 상태: 채택
- 날짜: 2026-10-20
- ADR-0030 2절의 "하루 10문제는 우선순위로 고를 때만 적용한다"에 예외를 하나 더한다. 우선순위, 개념마다 한 문제, 채점·기록 규칙, 아침·저녁 알림과 새벽 준비가 쓰는 "오늘 복습할 개념"(하루 상한 10 − 오늘 푼 수)은 그대로다.

## 맥락

복습 카드(MCP Apps)로 오늘 문제를 한 번에 풀 수 있게 되자, 10문제를 다 풀고도 더 풀고 싶을 때가 생겼다. 지금은 `get_review_set`이 하루 상한에 닿으면 `DAILY_LIMIT_REACHED`("내일 이어서 한다")만 돌려주고, 더 풀려면 "OO 문제 내줘"처럼 개념을 직접 골라야 한다. 하루 상한은 리뷰 부채를 막으려는 기본값이지 연습을 막으려는 것이 아니다(ADR-0030).

## 결정 (2026-10-20 사용자 결정)

1. **더 풀기 세트.** 사용자가 직접 더 풀겠다고 하면("더 풀래", "10문제 더", "더 내줘") `get_review_set`을 `more: true`로 부른다. 하루 상한과 상관없이 같은 우선순위(근본 원인 → 오늘 때가 되는 개념 → 헷갈린 개념 → 약점 → 새 개념)로 개념마다 한 문제씩 10문제(`count`를 주면 그 수)를 낸다. 기본 세트 크기 10은 그대로다.
2. **오늘 푼 개념은 뺀다.** 사용자 시간대(`Clock.timeZone`)로 오늘 채점한 풀이(`quiz_attempt.answered_at`)가 있는 문제의 개념은 고르지 않는다. 그 개념에 낼 문제가 남아 있어도 뺀다. 낸 시각은 기록하지 않으므로(`used_count`는 횟수뿐) "오늘 낸 개념"이 아니라 "오늘 푼 개념"으로 정한다. 낸 문제 중 아직 안 푼 문제는 다시 나올 수 있다(그 문제는 아직 풀 수 있는 문제다). 카드는 이미 있는 문제 ID를 건너뛴다.
3. **채점과 기록은 그대로다.** 더 풀기 세트의 풀이도 숙련도·FSRS 일정에 들어가고, 오늘 푼 수에도 들어간다.
4. **상한에 닿았을 때 알린다.** `DAILY_LIMIT_REACHED`의 글은 모델에게 `more`로 다시 부르면 더 낼 수 있다고 알린다. 서버 지침도 "더 풀래"에 `more: true`로 부르라고 한다.
5. **카드의 "10문제 더 풀기" 버튼.** 카드의 문제를 모두 채점했거나 카드가 상한에 닿은 상태면 버튼을 보인다. 누르면 호스트를 거쳐 `get_review_set`(`more: true`)을 부르고, 새 문제를 뒤에 붙여 첫 새 문제로 넘어간다. 채점한 슬라이드는 이전으로 다시 볼 수 있다.

## 결과

- 좋은 점
  - 카드나 채팅에서 개념을 고르지 않고도 이어서 풀 수 있다. 같은 날 같은 개념 문제가 되풀이되지 않는다.
  - 알림 개수와 새벽 준비는 바뀌지 않는다.
- 나쁜 점·감수할 것
  - 더 풀기 세트의 개념(특히 새 개념)은 새벽에 미리 만들지 않아 "만드는 중"이 많을 수 있다.
  - 더 풀수록 오늘 다시 볼 개념이 줄고 새 개념 비중이 커진다.
  - 모델이 사용자가 직접 요청하지 않았는데 `more`를 쓰면 하루 상한이 무의미해진다. 도구 설명과 서버 지침으로만 막는다.

## 검토한 대안

- **하루 상한을 없애거나 늘리기:** 리뷰 부채를 막는 기본값을 잃는다.
- **오늘 낸 개념까지 빼기:** 낸 시각을 기록하는 열이 필요하다. 안 푼 문제가 다시 나오는 것은 문제가 아니라서 지금 데이터(오늘 푼 풀이)로 정했다.
- **개념을 골라 더 풀게만 하기(지금대로):** 무엇을 더 풀지 사용자가 정해야 하고, 우선순위를 쓰지 못한다.

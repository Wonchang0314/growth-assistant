# ADR-0034: 퀴즈 품질 점검보다 원격 전환과 예약 작업으로 프로토타입을 먼저 만들고, 품질은 실제로 쓰면서 올린다

- 상태: 채택
- 날짜: 2026-10-19
- ADR-0018의 "먼저 로컬에서 기능과 퀴즈 품질을 검증하고, 그 뒤에 원격"과 ADR-0019의 "예약 작업 실행 방식은 핵심 기능을 검증한 뒤 정한다"를 바꾼다. 로컬 stdio 서버, 전송 분리, 서버 채점, 원격 전환 때 새 ADR로 정할 항목(공개 경로·인증·IP 제한·알림·MCP Apps)은 그대로다.

## 맥락

3단계 기능(FSRS·숙련도, 객관식 출제·검증, 복습·채점·신고, 약점, 변형, 상황 판단형)을 모두 만들고 출제 시험으로 정책을 한 번 조정했다(2026-10-18, ADR-0033). 남은 것은 Desktop에서 실제로 풀어 보며 품질을 확인하는 일인데, 맥미니 앞에 앉아야만 쓸 수 있어 사용이 드물고, 품질을 볼 재료(풀이 기록)가 쌓이지 않는다. 채점 기록은 아직 0개다.

사용자는 퀴즈 품질 점검과 확인을 원격으로 바꾼 뒤 실제로 쓰면서 해도 된다고 판단했다(2026-10-19). 모바일·아이패드에서 쓰고, 정해진 시각에 먼저 말을 걸어야 풀이가 쌓이고 품질 문제가 드러난다.

## 결정

1. **단계 순서를 바꾼다.** 3단계 남은 기능 → 4단계 원격 전환 → 5단계 예약 작업(프로토타입) → 6단계 실사용 품질 올리기.
   - 원격 전환을 예약 작업보다 먼저 한다. 예약 작업 후보(클라우드 예약 작업, 모바일 알림)가 대부분 원격 MCP를 전제하고, 원격이 되면 그날부터 실제로 쓸 수 있다.
2. **프로토타입에 넣는 예약 작업은 둘이다.** 새벽 동기화·문제 보충(Notion 증분 동기화와 경험 카드 추출, 오늘 복습할 개념의 문제를 미리 만들기)과 아침 복습 알림. 저녁 오늘의 주제, 주간 리포트, 무시 누적 감지, 숙련도 이력은 6단계로 미룬다.
3. **6단계로 미루는 것:** 퀴즈 품질 확인·점검(출제 품질, 평가 세트, 남은 열린 질문: 변형 비율·보기 수·빈칸 다시 넣기), 2단계 완료 확인(경험 카드 인용), 판단 사례 PENDING 검토. 같은 도구를 원격에서도 쓰므로 그때 한다.
4. **3단계에 남겨 지금 하는 것:** 학습 맥락에 숙련도·약한 선수 개념·근본 원인 싣기, quiz 레이어 구조 평가(ADR-0020).
5. 원격 전환의 세부(공개 경로, 인증, IP 제한, 알림, MCP Apps)와 예약 작업 실행 방식은 각 단계를 시작할 때 사용자에게 물어 새 ADR로 정한다.

## 결과

- 좋은 점
  - 모바일에서 쓰고 아침에 먼저 말을 걸어 풀이 기록이 쌓인다. 품질 문제를 실제 사용에서 찾는다.
  - 문제 보충이 새벽에 돌면 대화 중 "만드는 중" 대기가 줄어든다.
- 나쁜 점·감수할 것
  - ADR-0018이 피하려던 위험, 곧 품질을 확인하기 전에 공개 경로·인증·알림을 만들고 지켜야 하는 부담을 받아들인다.
  - 품질이 낮은 문제를 실제로 풀게 된다. 신고(`report_question`)와 출제 지침으로 그때그때 고친다.
  - 원격 서버가 인터넷에 열리므로 인증·IP 제한을 처음부터 제대로 해야 한다.

## 검토한 대안

- **지금 순서(로컬에서 품질 검증 → 예약 작업 → 원격):** 공개 부담 없이 품질을 먼저 보지만, 맥미니 앞에서만 써서 검증할 재료가 쌓이지 않는다.
- **예약 작업 먼저, 원격은 그 뒤:** 맥미니 안의 서버 예약 작업(동기화·보충)은 먼저 만들 수 있지만, 알림을 받고 바로 풀 곳이 없다.
- **3단계 남은 기능도 모두 6단계로:** 프로토타입이 더 빨라지지만, 사용자는 학습 맥락과 레이어 평가는 지금 하기로 했다.

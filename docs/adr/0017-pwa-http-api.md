# ADR-0017: Discord 대신 PWA를 인터페이스로, 앱은 HTTP API 서버로 바꾼다

- 상태: 채택
- 날짜: 2026-10-14

## 맥락

ADR-0003·0014는 Discord 개인 서버를 인터페이스로 골랐다. 튜터링 대화는 스레드로 충분하지만, 3·4단계 기능을 Discord로 만들면 아쉬운 점이 크다.

- 객관식 퀴즈, 연속 학습·보상 같은 화면을 버튼·임베드 안에서만 표현해야 한다.
- 알림이 Discord 채널 알림에 섞여, "새 복습이 있다", "오늘 풀었다" 같은 상태를 앱 아이콘 배지나 전용 알림으로 보여 줄 수 없다.
- 출제 지침 수정, 문제별 피드백(👎와 이유) 같은 관리 기능을 슬래시 명령·모달로 만들기 불편하다.

전용 앱을 만들려면 iPhone·iPad·Mac에서 맥미니와 통신해야 한다. Apple 개발자 계정(유료) 없이 SwiftUI 앱을 무료 프로비저닝으로 설치하면 7일마다 다시 서명해야 하고, 원격 푸시(APNs)를 쓸 수 없다. iOS 16.4부터는 홈 화면에 추가한 웹 앱(PWA)이 개발자 계정 없이 Web Push와 앱 배지를 받을 수 있다.

퀴즈·숙련도·먼저 말 걸기(3·4단계)는 아직 만들지 않았고, Discord에 묶인 코드는 `core/discord`와 `tutor/conversation/discord/`뿐이다. 유스케이스는 이미 discord.js를 모르므로(ADR-0015) 지금 바꾸는 비용이 가장 적다.

## 결정

Discord를 버리고 PWA를 유일한 인터페이스로 쓴다. NestJS 앱은 HTTP API 서버가 된다.

| 영역 | 선택 |
|---|---|
| 서버 | NestJS에 HTTP를 켠다. REST API, 튜터링 대화 응답은 SSE로 스트리밍한다 |
| API 계약 | `@nestjs/swagger`로 OpenAPI 명세를 만들고, 클라이언트 타입은 명세에서 생성한다 |
| 클라이언트 | PWA (홈 화면에 추가해 사용). 프론트엔드 프레임워크와 레포 구성은 1단계 설계에서 정한다 |
| 접근·인증 | Tailscale 망 안에서만 접근한다. `tailscale serve`로 HTTPS(`*.ts.net`)를 붙이고, 외부에 포트를 열지 않는다. 1인용이므로 앱 로그인은 두지 않는다 |
| 알림 | Web Push(VAPID). 구독 정보는 DB에 저장한다. 먼저 말 걸기(아침 복습, 오늘의 주제, 주간 리포트)는 푸시로 보내고, 누르면 해당 화면을 연다 |
| 운영 알림 | 앱이 죽었을 때도 받아야 하므로 앱 푸시와 별도 경로를 둔다(ntfy 등, 1단계 설계에서 정한다) |
| 호스팅 | ADR-0010 그대로 맥미니에서 launchd로 실행한다. 정적 파일도 같은 앱이 서빙한다 |

ADR-0014의 "HTTP 서버 없이 애플리케이션 컨텍스트만 띄운다"와 Discord 행, ADR-0015의 "처리기 모으기"(Discord 데코레이터 탐색)는 이 결정으로 대체한다. ADR-0015의 나머지(기능 모듈, 순수 함수 도메인 규칙, 외부 경계만 포트·어댑터, 의존 규칙)는 그대로이고, 입력 어댑터가 `discord/` 처리기에서 HTTP 컨트롤러로 바뀐다.

**전환 순서:** Discord 코드는 PWA에서 튜터링 대화가 실제로 동작한 뒤에 지운다. 그때까지 Discord 봇은 지금처럼 동작한다. 3단계부터는 처음부터 API·PWA 기준으로 만든다.

## 결과

- 좋은 점
  - 퀴즈·보상·리포트 화면을 원하는 대로 만든다. 알림과 배지를 앱 단위로 다룬다.
  - 백엔드(HTTP API, SSE, 푸시)와 프론트엔드를 모두 TypeScript로 만들어 풀스택 학습 목표와 맞는다.
  - 출제 지침 편집, 문제 피드백 같은 관리 기능을 화면으로 만들 수 있다.
  - Discord 상호작용 토큰 만료(15분), 3초 응답 제한, 메시지 2000자 분할 같은 제약이 사라진다.
- 나쁜 점·감수할 것
  - Discord가 주던 채팅 화면, 메시지 기록, 모바일 앱, 알림 전달을 직접 만들어야 한다.
  - iOS PWA 제약: Web Push는 홈 화면에 추가한 뒤에만 받는다. 백그라운드 동기화가 없고, 앱이 백그라운드로 가면 SSE가 끊긴다. 그래서 대화 응답은 서버에 저장해 두고, 다시 열 때 이어서 불러온다.
  - 모든 기기에 Tailscale을 설치하고 켜 두어야 한다. Tailscale 망 밖에서는 쓸 수 없다.
  - 1단계(튜터링 대화)를 다시 만들어야 해서 2~4단계가 그만큼 늦어진다.

## 검토한 대안

- Discord 유지: 대화에는 충분하지만, 퀴즈·보상·알림 UX의 한계가 3·4단계의 핵심 기능과 겹친다.
- SwiftUI 앱 + 무료 프로비저닝: 7일마다 다시 서명해야 하고, 원격 푸시를 쓸 수 없다. Swift를 새로 배워야 해 학습 목표(TS 백엔드)와도 어긋난다.
- SwiftUI 앱 + 유료 개발자 계정: 푸시와 장기 설치는 해결되지만 연 비용이 들고, Swift 학습 부담은 그대로다.
- Discord(대화)와 PWA(퀴즈·알림) 혼합: 인터페이스와 어댑터를 두 벌 유지해야 하고, 알림이 두 곳으로 나뉜다.
- 공개 인터넷에 노출하고 앱 로그인 구현: 1인용에 인증·보안 부담만 늘어난다.

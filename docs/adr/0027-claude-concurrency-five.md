# ADR-0027: `claude -p` 동시 실행을 5개로 올리고, 판단 사례는 카드를 그만큼 함께 처리한다

- 상태: 채택
- 날짜: 2026-10-18
- ADR-0012의 "동시 실행 2개"(ADR-0002에서 이어 온 원칙)를 바꾼다. 나머지(구독을 쓰는 서브프로세스, `ClaudeClient` 단일 경로, 격리, 도구 기본 비활성, `llm_call_log`)는 그대로다.

## 맥락

판단 사례 전체 실행은 경험 카드 260장 안팎에 카드마다 Sonnet 생성과 Opus 검증을 2~4번(가정 사례 폴백까지 가면 더) 부른다. 카드를 한 장씩 차례로 처리해 6~7시간이 걸릴 것으로 봤다. 동시 실행 제한이 2개라 카드를 함께 처리해도 크게 줄지 않는다. 사용자는 구독 사용량에 여유가 있다고 보고 5개까지 올리기로 했다(2026-10-18).

## 결정

- `claude -p` 동시 실행 상한을 5로 둔다(`claude.settings.ts`의 `maxConcurrency`). 넘는 호출은 기다린다.
- `ClaudeClient` 포트가 상한(`maxConcurrency`)을 내보이고, 판단 사례 추상화는 카드를 그 수만큼 함께 처리한다. 사용량 한도나 로그인 오류가 나면 새 카드는 시작하지 않고 멈춘다. 다시 실행하면 사례가 없는 카드부터 이어 간다.
- 선별(카드 40장을 한 번에)과 경험 카드 추출은 지금처럼 차례로 처리한다.

## 결과

- 좋은 점
  - 판단 사례 전체 실행이 2~3배 빨라질 것으로 본다.
  - 숫자는 설정 한 곳에만 있고, 유스케이스는 CLI 설정을 모르고 포트에서 끌어온다(ADR-0015).
- 나쁜 점·감수할 것
  - 사용량 한도에 더 빨리 닿는다. 한도에 걸리면 같은 구독을 쓰는 Claude 앱 대화와 다른 Claude Code 세션도 함께 막힌다. 한도에 자주 걸리면 다시 낮춘다.
  - 함께 처리하는 카드의 로그가 섞여 나온다.

## 검토한 대안

- **상한 2 그대로:** 안전하지만 전체 실행이 반나절 걸린다.
- **실행 진입점(`npm run abstract`)에 동시 처리 수 옵션을 따로 둔다:** 숫자가 두 곳에 생기고, 상한보다 크게 주면 의미가 없다.

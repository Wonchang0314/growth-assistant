# ADR-0042: 학습 범위를 개발에서 회계·업무 도메인으로 바꾸고, 학습 기록을 한 번 지우며, Notion 수집을 끈다

- 상태: 채택
- 날짜: 2026-11-27
- ADR-0022(시드 커리큘럼과 트랙 6개)와 ADR-0025(수집 개념의 트랙 배치와 운영 상위 개념)를 대체한다. ADR-0036 2절의 새벽 작업 "Notion 증분 동기화 → 경험 카드 추출"과 4절 `sync_now`를 바꾼다. 시드가 커리큘럼이라는 원칙, 시드 적재 규칙(YAML에서 빠진 시드 개념·트랙은 지움), 개념 하나는 트랙 하나에 속한다는 규칙, 복습·출제·채점·검증 흐름(ADR-0038~0041)은 그대로다.

## 맥락

서버는 개발(CS) 공부를 전제로 만들어졌다. 트랙 6개(JS/TS, 관계형 DB, 백엔드, IT 인프라, 네트워크, MCP)와 시드 개념 약 190개, 서버 지침·출제 프롬프트의 "개발자", "개발 개념", DB·커널 예시가 그 전제다. 사용자가 학습 목표를 바꿨다. 새 커리큘럼은 사용자가 받은 ERP 구축 실습 문서 12개(식품 수입 유통, 시험인증, 화장품, 전기통신 자재 도매, 가구 제조·유통, 법무법인, 의료기기 유통, 프레스 기계 제조, 멀티채널 커머스 등)에 나오는 회계와 업무 도메인의 용어·개념이다(2026-11-27 사용자 결정).

1. **옛 개념을 지울 수 없다.** 시드 적재는 YAML에서 빠진 시드 개념을 지우는데, 학습 기록·숙련도·문제·경험 카드 연결이 개념을 `ON DELETE` 없이 가리켜 외래 키 오류로 적재 전체가 취소된다. YAML만 바꿔서는 배포가 실패한다.
2. **수집이 새 트랙을 어지럽힌다.** 새벽 작업이 Notion을 동기화하고 바뀐 문서를 추출하며, 추출은 목록에 없는 개념을 "가장 가까운 트랙"에 새 개념으로 제안한다. 그대로 두면 개발 문서의 개념이 회계 트랙의 승인 대기 개념으로 쌓인다. 사용자는 Notion 수집이 필요 없다고 했다(2026-11-27).
3. **남은 경험 카드는 모두 개발 경험이다.** 경험 카드 545장과 판단 사례 279개는 새 개념에 연결되지 않는다.

## 결정 (2026-11-27 사용자 결정)

1. **지울 것과 남길 것 (D1).** 학습 기록(`study_note`, `study_note_concept`), 숙련도·복습 일정(`concept_mastery`), 문제·풀이(`quiz_question`, `quiz_attempt`), 하루 계획(`review_plan`), 경험 카드·판단 사례의 개념 연결(`experience_concept`, `decision_case_concept`), 개념 그래프 전체(`concept_edge`, `concept`: 시드·수집·대화에서 생긴 것·거절된 것 모두), 트랙(`track`)을 지운다. Notion 원문·청크·동기화 커서, 경험 카드, 판단 사례(개념 연결만 끊김), OAuth, 예약 작업 기록, LLM 호출 로그, `app_setting`(출제 지침 포함)은 남긴다. "학습 목표 초기화"는 개념과 그 진도이고, 경험은 사용자의 이야기라 다시 쓰려면 다시 추출하면 된다.
2. **초기화는 일회성 데이터 마이그레이션이다 (D2).** `0015_reset_curriculum.sql`이 위 테이블을 외래 키 순서(`quiz_attempt` → `quiz_question` → `review_plan` → `concept_mastery` → `study_note_concept` → `study_note` → `experience_concept` → `decision_case_concept` → `concept_edge` → `concept` → `track`)로 DELETE한다. 지울 범위가 SQL에 드러나게 `TRUNCATE … CASCADE`는 쓰지 않는다. 배포가 마이그레이션 → 시드 적재 순서라 한 번 배포하면 지우기와 새 커리큘럼 적재가 함께 끝난다(선례 `0013_concept_only_quiz`).
3. **Notion 수집은 끈다 (D3).** 새벽 작업은 수집 단계(동기화 → 추출)를 하지 않고 문제 준비(오늘 계획과 문제 미리 만들기)만 한다. MCP 도구 `sync_now`·`sync_status`와 경험 카드·판단 사례 도구 `search_experience`·`list_pending_cases`·`review_case`를 등록에서 빼고 서버 지침의 해당 줄을 지운다. 수집 코드, CLI(`npm run sync`·`extract`·`abstract`), 테이블, 데이터는 남긴다(되돌리기 쉽게). 수집 프롬프트는 돌리지 않으므로 고치지 않는다. 코드까지 지우는 일은 따로 정한다.
4. **다루는 범위 (D4).** 회계(재무회계·결산·세금), 채권·채무, 영업·유통, 구매·재고·물류, 무역·외환, 생산·제조, 기준정보·내부통제, 산업별 업무(시험인증·화장품·법무·의료기기)를 넣는다. 실습의 ERP 구현 요구와 IT 개념(RBAC 구현, 멱등성 등), FDE 방법론(MECE, 스코프 산정 등)은 뺀다. 기준은 한국 실무다. 회계는 K-IFRS를 중심으로 쓰고 일반기업회계기준과 갈리는 곳은 설명에 밝힌다. 법령에 기대는 사실은 시드 설명을 쓸 때 공식 자료로 확인한다.
5. **트랙 8개, 가중치는 모두 0.2 (D5).** `accounting`(회계 원리와 결산), `receivable`(채권·채무와 여신), `sales`(영업·유통 채널), `inventory`(구매·재고·물류), `trade`(무역·외환), `manufacturing`(생산·제조), `control`(기준정보와 내부통제), `industry`(산업별 업무). 시드는 `src/core/knowledge/seed/<트랙>.yaml` 8개, 개념 약 120개이고 형식 설명은 `accounting.yaml` 머리말에 둔다. 개념 하나는 책 한 절 크기이고 트랙마다 최상위 개념 하나 아래에 둔다. 같은 이름이 두 트랙에 걸리면 "돈의 기록"은 `accounting`·`receivable`, "물건과 업무의 흐름"은 나머지 트랙이 맡고 `RELATED`로 잇는다(예: 원가흐름 가정의 선입선출과 실물 출고 순서의 선입선출).
6. **문구를 주제와 상관없게 고친다.** 서버 지침과 출제 프롬프트에서 "개발자", "개발 개념", "기술 용어"를 빼고 예시를 회계·재고로 바꾼다. 웹 검색으로 확인할 사실은 "법령·회계기준·세율·제도·버전처럼 바뀔 수 있는 사실"로 넓힌다. 출제·채점·검증 규칙은 그대로다.

## 결과

- 좋은 점
  - 한 번 배포로 옛 학습 상태가 지워지고 새 커리큘럼이 적재된다. 배포 순서를 따로 기억하지 않아도 된다.
  - 새벽 작업이 Notion을 읽지 않아 새 트랙에 개발 개념이 쌓이지 않고, 새벽 사용량이 줄어든다.
  - 수집 코드와 데이터를 남겨 다시 켜기 쉽다.
- 나쁜 점·감수할 것
  - **배포 직전 백업을 꼭 한다**(`docs/ops.md` "백업"). 지운 학습 기록·숙련도·문제는 이 백업에만 남는다.
  - 초기화 전 백업에는 0015 적용 기록이 없어, 복원한 뒤 마이그레이션을 돌리면(배포 포함) 0015가 다시 지운다. 옛 데이터를 보려면 임시 컨테이너에 복원한다.
  - 경험 카드·판단 사례는 남지만 개념 연결이 끊겨 학습 맥락·채점 결과에 나오지 않고, 찾거나 검토하는 도구도 등록되지 않는다. 다시 쓰려면 도구를 등록하고 새 개념으로 다시 추출해야 한다.
  - Claude 프로젝트 지침(`docs/claude-project-instructions.md`)은 사용자가 Claude·ChatGPT 프로젝트에 다시 붙여 넣어야 바뀐다.
  - 출제 지침(`app_setting`)은 남으므로, 개발에만 맞는 규칙이 있으면 배포 전에 사용자에게 보여 주고 지울지 묻는다.
  - 숙련도·약점 데이터가 처음부터 다시 쌓여, 한동안 복습은 새 개념 위주다.

## 검토한 대안

- **수동 초기화 CLI(`npm run reset-learning`):** 배포 전에 따로 돌려야 하고, 빠뜨리면 시드 적재가 외래 키로 실패한다. 실패해도 데이터는 안전하지만 순서를 기억해야 한다.
- **`TRUNCATE … CASCADE`:** 짧지만 무엇이 지워지는지 SQL에 드러나지 않는다.
- **Notion 수집을 두고 추출 프롬프트에 새 트랙 설명을 넣기:** 남은 문서가 모두 개발 경험이라 회계 트랙에 맞는 개념이 나오지 않는다(사용자가 수집이 필요 없다고 함).
- **수집 코드·테이블까지 지우기:** 되돌리기 어렵다. 따로 정한다.
- **FDE 방법론 트랙을 더하기, 트랙마다 가중치를 다르게 두기:** 사용자가 고르지 않았다(2026-11-27).

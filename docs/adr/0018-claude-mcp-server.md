# ADR-0018: PWA 대신 Claude 앱을 인터페이스로, 앱은 MCP 서버로 바꾸고 먼저 로컬에서 검증한다

- 상태: 일부 대체됨(ADR-0019: 아침·저녁 학습)
- 날짜: 2026-10-14

## 맥락

ADR-0017은 Discord 대신 PWA + HTTP API를 골랐다. 그러려면 채팅 화면, 퀴즈 화면, SSE 스트리밍, Web Push, 서비스 워커, 프론트엔드 빌드·배포를 직접 만들고 유지해야 한다. 지금 목표는 유지보수 부담을 최소로 하는 것이다.

Claude 앱은 MCP 서버를 붙여 도구로 쓸 수 있다. 그러면 튜터링 대화는 Claude 앱의 모델이 맡고, 백엔드는 도구(복습 문제 조회, 답안 채점, 약점 조회, 경험 카드 검색, 학습 기록)만 제공하면 된다. 채팅 화면, 대화 기록, 모바일 앱을 만들 필요가 없다.

Claude 앱에 MCP 서버를 붙이는 방법은 두 가지다.

- **로컬:** Claude Desktop이 내 Mac에서 서버 프로세스를 직접 띄운다(stdio). 인증·공개 노출이 필요 없지만 이 Mac의 Desktop 앱에서만 쓴다.
- **원격(커스텀 커넥터):** Claude가 Anthropic 클라우드에서 서버로 접속한다. 웹·데스크톱·iOS에서 모두 쓰지만, 서버를 인터넷에 공개하고 인증을 붙여야 한다. 조사 결과(2026-10-14):
  - 고정 헤더 인증(Request headers)은 베타라 일부 조직에만 열려 있고, 이 계정에서는 쓸 수 없었다. 모든 플랜에서 되는 인증은 OAuth다.
  - Claude의 외부 요청 IP 대역은 `160.79.104.0/21`인데, 모든 Claude 사용자가 공유하므로 IP 제한만으로는 인증을 대신할 수 없다.
  - Tailscale Funnel로 공개할 수 있지만 주소가 공개 인증서 기록에 남는다. Funnel 뒤에서 원래 접속 IP를 알 수 있는지는 확인하지 못했다.
  - 사설망 연결(MCP tunnels)은 Enterprise 플랜 전용이다.
  - 서버는 Claude 앱에 직접 알림을 보낼 수 없다. Claude 예약 작업의 완료 푸시 여부는 문서로 확인되지 않았다.

이 프로젝트에서 가장 불확실한 것은 인프라가 아니라 **튜터링과 퀴즈의 품질**이다. 원격 공개·OAuth·알림을 먼저 만들면, 품질을 확인하기 전에 버릴 수도 있는 작업에 시간을 쓴다.

## 결정

PWA를 만들지 않고 Claude 앱을 인터페이스로 쓴다. NestJS 앱은 MCP 서버가 된다. **먼저 이 Mac의 Claude Desktop에 로컬로 붙여** 기능과 퀴즈 품질을 검증하고, 그 뒤에 원격 커넥터로 바꿔 모바일·아이패드로 넓힌다.

| 영역 | 선택 |
|---|---|
| 인터페이스 | 맥미니(서버를 돌리는 Mac)의 Claude Desktop (대화, Cowork) |
| 연결 | 로컬 MCP 서버(stdio). Claude Desktop이 `node dist/mcp-stdio.js` 같은 진입점을 띄운다. 공식 TypeScript SDK(`@modelcontextprotocol/sdk`)를 쓴다 |
| 인증·공개 | 없음. 로컬 프로세스이고 네트워크에 열지 않는다 |
| 전송 분리 | 도구 처리기와 유스케이스는 전송 방식(stdio·HTTP)을 모르게 둔다. 원격으로 바꿀 때 Streamable HTTP 진입점만 추가한다 |
| 튜터링 대화 | Claude 앱이 한다. 서버는 대화를 저장하지 않고, 대화 중 드러난 약점·관찰은 Claude가 도구로 기록한다(서버 `instructions`, 도구 설명, Claude 프로젝트 지침으로 유도) |
| 채점 | 서버가 한다. 도구 결과에 아직 풀지 않은 문제의 정답을 싣지 않고, `submit_answer`가 채점 결과만 돌려준다 |
| 퀴즈 화면 | 텍스트로 묻고 답한다. MCP Apps 화면은 원격 전환 때 함께 검토한다 |
| 아침·저녁 학습 | Claude 예약 작업이 정해진 시각에 도구를 불러 복습 문제·오늘의 주제를 만든다. 로컬 MCP는 Anthropic 클라우드에서 닿지 않으므로 클라우드 루틴은 쓸 수 없고, 이 Mac에서 실행되는 예약 작업(Cowork 예약 작업, 안 되면 Claude Code 데스크톱 예약 작업)을 쓴다. Mac이 깨어 있고 Desktop 앱이 켜져 있어야 한다 |
| 백그라운드 LLM | 추출, 출제·검증, 서술형 채점처럼 대화 밖에서 도는 작업은 `claude -p`를 그대로 쓴다(ADR-0012) |
| 운영 알림 | 이 단계에서는 따로 두지 않는다. `AdminNotifier`는 로그 기록으로 대신하고, 원격 전환 때 알림 경로를 정한다 |
| 도구 범위 | 읽기와 학습 기록만 둔다. 삭제처럼 되돌릴 수 없는 도구는 만들지 않는다 |
| 호스팅 | 맥미니 그대로(ADR-0010). MCP 서버는 Claude Desktop이 필요할 때 띄우고, 서버 예약 작업(문제 풀 보충 등)이 필요해지면 launchd 상시 실행 앱에 둔다. DB는 지금처럼 Docker PostgreSQL |

ADR-0017 전체를 대체한다. ADR-0015의 기능 모듈·포트·어댑터 구조는 그대로이고, 입력 어댑터가 MCP 도구 처리기가 된다.

**전환 순서:** Discord 코드는 로컬 MCP로 튜터링 흐름이 동작한 뒤에 지운다. `tutor/conversation`의 세션·유휴 종료·대화 요약은 Claude 앱이 대신하므로 그때 함께 정리한다.

**원격 전환 때 새 ADR로 정할 것:** 공개 경로(Tailscale Funnel, Cloudflare Tunnel), 인증(OAuth 2.1 최소 구현, 또는 그때 열려 있으면 고정 헤더 인증), IP 제한, 학습 알림(Claude 예약 작업 푸시, ntfy), 운영 알림(ntfy, 헬스체크 감시), MCP Apps 퀴즈 화면.

## 결과

- 좋은 점
  - 채팅 화면, 프론트엔드, 푸시, 인증, 공개 경로를 만들지 않고 바로 튜터링·퀴즈 품질을 검증한다.
  - 대화 품질이 Claude 앱 그대로다(웹 검색, 파일 첨부, 모델 선택 포함). 대화용 `claude -p` 호출·세션 관리가 사라진다.
  - 전송 방식을 분리해 두므로 원격 전환 때 도구 코드를 다시 쓰지 않는다.
- 나쁜 점·감수할 것
  - 맥미니의 Claude Desktop에서만 쓴다. 모바일·아이패드는 원격 전환 뒤에 쓴다.
  - 아침·저녁 예약 작업은 맥미니가 깨어 있고 Desktop 앱이 켜져 있을 때만 돈다. 잠자기 방지 설정이 필요하다.
  - 예약 작업이 로컬 MCP를 쓸 수 있는지, 실행 결과를 휴대폰에서 볼 수 있는지는 문서로 확인되지 않아 1단계에서 검증한다.
  - 대화 중 약점 기록은 Claude가 도구를 부르는지에 달렸다. 반드시 기록된다는 보장이 없다.
  - 대화 사용량은 구독 한도에서 나간다.
  - Discord 봇용 운영 스크립트(`ops/`)는 서버 예약 작업이 생길 때 MCP 기준으로 고쳐 쓴다.

## 검토한 대안

- PWA + HTTP API 유지(ADR-0017): 화면과 알림을 원하는 대로 만들 수 있지만, 채팅 UI·푸시·프론트엔드를 모두 유지해야 한다.
- 처음부터 원격 커스텀 커넥터: 모바일까지 바로 쓰지만, 품질을 확인하기 전에 OAuth 서버·공개 경로·IP 제한·알림을 만들고 지켜야 한다.
- 로컬 HTTP 서버 + stdio 중계(`mcp-remote`): 원격과 같은 엔드포인트를 쓰지만 외부 패키지와 상시 실행 프로세스가 하나 더 필요하다. 전송 분리로 같은 효과를 얻는다.
- Claude Code 클라우드 루틴으로 아침·저녁 실행: Anthropic 클라우드에서 돌아 로컬 MCP에 닿지 않는다. 원격 전환 뒤에 다시 검토한다.

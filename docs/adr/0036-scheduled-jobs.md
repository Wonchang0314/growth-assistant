# ADR-0036: 예약 작업은 상시 실행 HTTP 서버 안의 스케줄러로 돌리고, 아침 복습은 Cowork 예약 작업을 시험한 뒤 ntfy로 보완한다

- 상태: 채택
- 날짜: 2026-10-20
- ADR-0034가 5단계를 시작할 때 정하기로 한 예약 작업 실행 방식과 알림 경로를 정한다. ADR-0035의 상시 실행(LaunchAgent)과 ntfy를 그대로 쓴다.

## 맥락

4단계에서 MCP HTTP 서버가 LaunchAgent로 상시 실행되고 원격 커넥터로 웹·Desktop·모바일에서 쓰게 됐다(ADR-0035). 5단계 프로토타입의 목표는 아침에 휴대폰으로 알림을 받고 바로 복습을 풀어 채점 기록이 쌓이는 것이다(ADR-0034). 그 전에 새벽에 Notion 변경을 가져오고, 오늘 복습할 개념의 문제를 미리 만들어 "만드는 중" 대기를 줄인다.

조사([원격 전환·예약 작업 조사](../research/2026-10-19-remote-and-scheduling.md) 5절): Cowork 예약 작업은 2026-10-06부터 클라우드에서 돌고 커넥터를 쓰지만, 원격 커스텀 커넥터를 실제로 부르는지와 끝난 뒤 휴대폰 알림이 오는지는 문서로 확인되지 않았다. 서버가 Claude 앱에 먼저 말을 거는 방법은 없고, 서버에서 시작하는 경로는 외부 알림(ntfy)뿐이다. NestJS에는 `@nestjs/schedule`(크론)이 있지만 놓친 실행을 기억하지 않는다.

## 결정

1. **예약 작업은 MCP HTTP 서버 프로세스 안의 스케줄러(`core/scheduler`, `@nestjs/schedule`)로 돌린다.** 시각은 `Asia/Seoul`. 작업마다 마지막 실행을 DB에 남기고, 그 시각에 프로세스가 꺼져 있어 놓친 실행은 다음에 서버가 뜰 때 한 번만 따라잡는다. 같은 작업이 겹쳐 돌지 않게 한다. 실패는 ntfy 운영 알림(같은 종류 1시간 묶기)으로 알린다.
2. **새벽 04:00 작업:** Notion 증분 동기화 → 새로 바뀐 문서의 경험 카드 추출 → 새 경험 카드의 판단 사례 추상화 → 오늘 복습할 개념 중 문제가 없는 개념의 문제를 미리 만들기(하룻밤 최대 10개 개념). 앞 단계가 실패해도 뒤 단계는 할 수 있는 만큼 한다.
3. **아침 복습 알림은 두 경로를 둔다.**
   - Cowork 예약 작업(클라우드)이 매일 07:30에 원격 커넥터로 `get_review_set`을 불러 문제를 준비한다. 사용자가 Claude 앱에서 만들고, 하루 시험해 알림과 이어 풀기가 되면 이 경로를 주로 쓴다.
   - 서버가 ntfy로 학습 알림을 보낸다. 07:30 아침 알림("오늘 복습 N개")은 Cowork 경로가 안 될 때 켜는 설정으로 두고, 21:00 저녁 알림은 그날 채점 기록이 없을 때만 보낸다. 학습 알림은 운영 알림과 같은 토픽을 쓰되 종류를 나눈다.
4. **`sync_now` 도구를 더한다.** 대화에서 Notion 동기화를 바로 시작하고, 진행 상황은 `sync_status`로 본다. 새벽 작업과 겹치지 않게 같은 잠금을 쓴다.
5. ntfy 운영 알림 중 리프레시 토큰 재사용(탈취 의심)만 우선순위를 `urgent`로 올린다.

## 결과

- 좋은 점
  - 프로세스·배포·로그가 하나다. 스케줄러가 이미 떠 있는 서버의 DB 연결과 `claude -p` 클라이언트를 쓴다.
  - 놓친 실행을 DB로 기억해 맥이 꺼져 있던 날도 켜지면 한 번 돌고, 여러 번 몰아서 돌지 않는다.
  - Cowork가 안 돼도 ntfy로 알림은 반드시 온다.
- 나쁜 점·감수할 것
  - 예약 작업이 서버와 같은 이벤트 루프에서 돈다. CPU를 오래 쓰는 일을 넣으면 `/mcp` 응답이 늦어진다(지금 작업은 대부분 I/O와 서브프로세스).
  - 예약 작업이 서버를 죽이면 `KeepAlive`가 다시 띄우지만 그동안 커넥터가 끊긴다.
  - 새벽 작업이 매일 구독 사용량을 쓴다(추출·추상화·출제). 하룻밤 출제 상한으로 묶는다.
  - ntfy 알림을 누른 뒤에는 Claude 앱에서 "복습하자"를 직접 말해야 한다.

## 검토한 대안

- **별도 진입점 + launchd 시간 예약(`StartCalendarInterval`):** 서버와 격리되지만 LaunchAgent가 하나 늘고, 놓친 실행 처리가 launchd 규칙(잠자기에서 깨어날 때만 실행, 꺼져 있던 경우는 넘어감)에 묶인다.
- **Cowork 예약 작업이 새벽 보충까지 도구로 부르기:** 서버에 스케줄러가 없지만 동기화·추출처럼 오래 걸리는 일을 MCP 도구로 열어야 하고 실패 감지·재시도가 Claude에 달린다.
- **처음부터 ntfy 아침 알림만:** 확실하지만 알림을 누른 뒤 한 단계가 더 있다. Cowork 경로를 먼저 시험한다.

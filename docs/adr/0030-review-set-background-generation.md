# ADR-0030: 복습 문제는 풀에 있는 것만 바로 내고, 없는 개념의 문제는 뒤에서 만든다

- 상태: 채택
- 날짜: 2026-10-18
- 설계 문서 7.3의 "풀에 VALID인 문제가 없으면 즉석 생성 + 검증"을 바꾼다. 개념 선택 우선순위, 하루 10문제, 채점 규칙(8장)은 그대로이고, 아래에서 구체화한다.

## 맥락

3단계에서 복습·채점 도구(`get_review_set`, `submit_answer`, `report_question`)를 만들었다. 설계는 문제 풀에 문제가 없으면 `get_review_set` 안에서 즉석으로 만들고 검증한다고 했다. 그런데 문제 하나를 만드는 데 `claude -p`를 2~4번(출제 Sonnet, 검증 Opus) 부르고(ADR-0029), 개념마다 한 문제씩이면 그만큼 늘어난다. 동시 실행 5개로 나눠도 1~2분 넘게 걸릴 수 있다. MCP 클라이언트는 요청 하나를 오래 기다리지 않는다(공식 TypeScript SDK 클라이언트의 기본 요청 타임아웃은 60초이고, Claude Desktop이 이 값을 바꾸는지는 확인하지 못했다). 문제 풀 보충(03:00 예약 작업)은 4단계에 생긴다.

## 결정

### 1. 없는 문제는 뒤에서 만든다

- `get_review_set`은 풀에 있는 문제(검증 통과, 신고 안 됨, 아직 안 푼 문제)만 바로 돌려준다. 문제가 모자란 개념은 MCP 서버 프로세스 안에서 뒤에서 만들기 시작하고, 결과에 "만드는 중"인 개념 이름을 싣는다. Claude는 있는 문제부터 내고, 다 풀면 다시 불러 새 문제를 받는다.
- 같은 개념을 겹쳐 만들지 않는다(이미 낸 핵심을 서로 몰라 같은 문제가 나온다). 개념 하나의 문제는 차례로 만든다.
- 유형은 그 개념에 검증을 통과한 문제가 적은 쪽(객관식·빈칸)으로 고른다.
- 만들다 실패하면 로그에 남기고 넘어간다. 다음 `get_review_set`이 다시 만들기 시작한다.

### 2. 문제 고르기 (설계 7.3 구체화)

- 개념 순서: ① 복습할 때가 된 개념(예정일이 이른 것부터) → ② 헷갈렸다고 기록한 뒤 아직 퀴즈로 확인하지 않은 개념(최근 것부터), 약점 개념(약점 점수가 높은 것부터) → ③ 일정이 없는 승인된 개념(트랙 가중치에 비례해 뽑음, 가중치 0인 트랙은 뽑지 않음). 개념마다 한 문제다.
- 하루 10문제는 사용자 시간대의 그날 채점한 풀이 수로 센다. 우선순위로 고를 때만 적용하고, 사용자가 개념을 골라 달라고 했을 때("OO 문제 내줘", 기본 3문제)는 세지 않는다. 사용자가 원해서 더 연습하는 것은 막지 않는다.
- 낸 문제는 `used_count`를 올린다. 풀기 전에는 다음에도 다시 낼 수 있다.
- 변형 문제(`key_point`, `variant_of`)는 다음 작업이다. 그 전까지는 같은 개념의 아직 안 푼 문제를 낸다.

### 3. 채점과 신고

- 객관식 답은 보기 번호("2", "2번")나 보기 글로 받는다. 어느 보기인지 모르면 채점하지 않고 번호로 다시 보내라고 돌려준다.
- 확신도가 빠지면 애매(UNSURE), 힌트 여부가 빠지면 힌트를 쓴 것으로 본다(설계 7.3). 힌트를 쓴 풀이는 일정만 바꾸고 숙련도에는 넣지 않는다(ADR-0028).
- 같은 오개념이 그 개념의 풀이에서 전에도 나왔으면 반복 오개념이다(신고된 문제의 풀이는 세지 않음).
- 신고하면 그 문제를 다시 내지 않고, 그 문제를 푼 적이 있으면 그 개념의 숙련도·약점·FSRS 일정을 신고된 문제의 풀이를 뺀 기록으로 처음부터 다시 계산한다(사용자 결정 2026-10-18). 신고 뒤 그 문제를 다시 풀어도 숙련도에 넣지 않는다.
- 개념 병합 때 문제는 대상 개념으로 옮긴다(ADR-0028의 병합 참여 포트). 풀이는 문제를 따라간다.

## 결과

- 좋은 점
  - 도구 호출이 LLM을 기다리지 않아 끊기지 않는다. 채점은 LLM 없이 즉시 끝난다.
  - 개념을 처음 복습할 때도 흐름이 멈추지 않는다. 있는 문제로 먼저 풀고, 그동안 다음 문제가 만들어진다.
- 나쁜 점·감수할 것
  - 풀이 비어 있으면 첫 `get_review_set`은 문제 없이 "만드는 중"만 돌려준다. 1~2분 뒤 다시 불러야 한다. `npm run quiz`로 미리 채우거나, 4단계 문제 풀 보충이 생기면 줄어든다.
  - 뒤에서 만드는 작업은 MCP 서버 프로세스 안에 있어, Desktop을 닫으면 끊긴다. 다음에 다시 만든다.
  - 새 개념(③)은 대화에서 다룬 적 없는 개념이라 처음 보는 문제일 수 있다. 써 보고 ③의 비율을 줄일지 정한다.

## 검토한 대안

- **설계대로 즉석 생성을 기다리기:** 가장 단순하지만, 호출이 타임아웃으로 끊기면 만든 문제도 사용자에게 가지 않는다.
- **MCP 진행 알림(progress)으로 타임아웃 늘리기:** 클라이언트가 진행 알림으로 타임아웃을 늘리는지 Claude Desktop에서 확인하지 못했다. 확인되면 다시 본다.
- **Claude가 대화 안에서 직접 문제를 만들기:** 검증 단계와 문제 풀(변형, 신고, 숙련도 연결)을 잃는다(ADR-0009·0029).

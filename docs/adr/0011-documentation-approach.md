# ADR-0011: 문서는 C4 + ADR, 작업 계획은 세션 안에서 관리한다

- 상태: 채택
- 날짜: 2026-10-13

## 맥락

1인 프로젝트에 맞는 문서 체계가 필요하다. 상세 작업 계획 문서는 코드와 쉽게 어긋난다.

## 결정

- 루트 `CLAUDE.md`: 짧은 프로젝트 설명, 기술 스택, 패키지 구조, 명령, 문서 위치
- `docs/specs/`: 기능 설계
- `docs/architecture/`: C4 레벨 1~3 (Mermaid). 레벨 4(코드)는 생략한다
- `docs/adr/`: 결정 기록
- `docs/roadmap.md`: 단계별 진행 상태만 기록한다
- 상세 작업 계획은 세션 안에서만 관리하고 저장소에 남기지 않는다

## 결과

- 좋은 점: 문서가 가볍고, "어디까지 했나"는 roadmap이, "왜 이렇게 했나"는 ADR이 답한다.
- 나쁜 점: 세션이 끊기면 세부 작업 순서는 다시 세워야 한다.

## 검토한 대안

- arc42: 12개 섹션 템플릿이라 1인 프로젝트에는 무겁다. 필요한 내용은 설계 문서에 이미 있다.
- GitHub Issues로 진행 상태 관리: 원격 레포가 아직 없고, roadmap 파일 하나로 충분하다.

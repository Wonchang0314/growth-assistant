# ADR-0041: 개념 문제에서 조직 문자열 게이트를 빼고, 모델 검증은 Haiku가 질문 없이 보기만 보고 풀어 보는 것 하나로 한다

- 상태: 채택
- 날짜: 2026-10-25
- ADR-0029 1절의 검증 단계(Opus가 정답을 숨기고 풀기)와 모양 검사의 패턴 게이트, 설계 문서 7.3 "변형 문제"의 비교 호출(Opus)을 바꾼다. 출제(Sonnet), 코드 모양 검사(보기·정답 보기·오개념·정답만 긴 보기·빈칸·길이 상한), 보기 섞기, 한 번 다시 쓰기, 변형의 코드 모양 검사(질문·보기·정답 보기가 원래와 같은지)는 그대로다. 판단 사례의 패턴 게이트(ADR-0024)도 그대로다.

## 맥락

하루 계획(ADR-0040) 뒤에도 아침 복습이 10문제를 다 채우지 못했다. 원인은 FSRS나 각도 조건이 아니라 검증 통과율이었다. 새벽 작업이 문제를 만든 개념 수는 10-22부터 3/17, 2/19, 1/20, 3/18이었다. 10-22 이후 INVALID 97개는 이렇게 나뉜다.

1. **조직 문자열 게이트 13개.** 출제 프롬프트가 "확인한 문서 주소를 referenceMaterial에 적는다"고 시키는데, 판단 사례용 패턴 게이트(ADR-0024)가 그 URL(`support.claude.com`, `rfc-editor.org`, `web.dev` 등)을 걸었다. 개념 문제는 출제에 경험을 싣지 않아(ADR-0038) 회사 맥락이 샐 곳이 없다.
2. **Opus 검증 84개.** 변형 비교 18개를 포함한다. 결함과 개선 제안("~로 명시하면 더 정확하다")을 나누지 않고 한 줄이라도 있으면 떨어뜨렸다.

사용자는 기계 검사는 코드 모양 검사로 두고, 모델 검증은 싼 모델로 보기만 보고 풀기 하나만 하기로 정했다(2026-10-25 사용자 결정).

## 결정

1. **개념 문제에서 조직 문자열 게이트를 뺀다.** `draftProblems`는 구조와 길이만 본다. 출제 프롬프트의 "기계가 모양으로 검사한다" 안내도 지운다.
2. **모델 검증은 보기만 보고 풀기 하나다(`QUIZ_VERIFICATION`, Haiku).** 객관식의 보기 4개만(질문·정답 표시·오개념·해설·근거 없이) 주고 정답일 것 같은 보기와 그렇게 고른 모양 단서(`cue`)를 받는다. 정답을 고르고 단서를 대면 걸리고, 그 단서를 걸린 이유로 남겨 다시 쓰게 한다.
   - 단서는 모양만이다: 혼자 길거나 자세함, 혼자 다른 형식(메타 보기, 혼자 다른 결론), 다른 보기들의 단정 표현, 조각 다수결. 개발 지식으로 맞는 말을 골랐으면 단서가 아니다(null). 그것은 문제가 제 역할을 하는 것이다.
   - 단서 없이 맞힌 것은 넘긴다. 보기 4개면 짐작으로도 넷에 하나는 맞는다.
3. **빈칸은 모델 검증을 하지 않는다.** 보기가 없어서다. 빈칸은 복습에서 내지 않는다(ADR-0033).
4. **변형은 코드 모양 검사만 한다.** Opus 비교 호출(같은 핵심인가, 외워서 풀 수 있는가)을 지운다.

## 결과

- 좋은 점
  - 통과율을 깎던 오탐(출처 URL)과 개선 제안 탈락이 없어진다.
  - 검증 호출이 Opus 한두 번에서 Haiku 한 번으로 줄어, 새벽 20개 출제의 사용량과 시간이 준다.
  - 시험(2026-10-25, 기존 문제 14개): 처음 프롬프트(내용으로 맞는 말을 골라도 단서로 침)는 Opus를 통과한 9개 중 6개를 걸었다. 모양 단서만으로 좁히자 9개 모두 통과했고, Opus가 "보기 하나만 길고 자세하다"로 건 문제(229)는 같은 이유로 걸었다. Opus가 "메타 보기"로 건 문제(223)는 놓쳤다.
- 나쁜 점·감수할 것
  - **표시된 정답이 맞는지 아무도 보지 않는다.** 사실이 틀렸거나, 정답이 여럿이거나, 엔진·버전 조건이 빠진 문제가 VALID가 된다. 사용자가 풀다 `report_question`으로 신고해야 걸러진다. 신고가 늘면 Opus 풀이 검증(결함만 INVALID)을 다시 검토한다.
  - 변형이 원래 답을 외워서 풀리는지는 코드가 같은 글만 잡는다.
  - Haiku 판정은 실행마다 달라질 수 있다.

## 검토한 대안

- **Opus 검증을 두고 결함과 개선 제안을 나눠 결함만 INVALID:** 틀린 정답을 막지만 Opus 호출이 그대로다(사용자가 고르지 않음).
- **Opus 검증 앞에 Haiku 보기만 풀기를 더하기:** 통과율 문제는 그대로다.
- **기준 자료의 URL만 게이트에서 빼기:** 질문·해설의 공개 도메인(`web.dev`)은 여전히 걸리고, 지킬 회사 맥락이 없는 검사가 남는다.
